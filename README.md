# Task Tracker API

A REST API for managing personal to-do tasks. Users register, log in and manage their own tasks, and no user can see or change another user's tasks.

I built this to learn backend engineering fundamentals: authentication, access control, database design, migrations, automated testing, containerisation and CI.

## Features

- User registration and login with JWT access tokens
- Passwords stored as Argon2 hashes, never in plain text
- Create, read, update and delete tasks (full CRUD)
- Per-user data isolation: every task query is scoped to the logged-in user
- Input validation with Pydantic (invalid data returns 422)
- Database schema managed with Alembic migrations
- Automated tests with pytest against a separate test database
- Docker and Docker Compose setup
- GitHub Actions runs the tests and builds the Docker image on every push

## Tech stack

Python 3.12, FastAPI, Pydantic, SQLAlchemy, PostgreSQL, Alembic, pytest, Docker, GitHub Actions

## API overview

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/health` | No | Health check |
| POST | `/users` | No | Register a user |
| POST | `/login` | No | Log in and receive an access token |
| GET | `/users/me` | Yes | Current user |
| POST | `/tasks` | Yes | Create a task |
| GET | `/tasks` | Yes | List your tasks |
| GET | `/tasks/{id}` | Yes | Get one of your tasks |
| PATCH | `/tasks/{id}` | Yes | Update one of your tasks |
| DELETE | `/tasks/{id}` | Yes | Delete one of your tasks |

Interactive documentation is generated by FastAPI at `/docs` when the server is running.

## Run with Docker

Requires Docker Desktop.

1. Create a `.env` file in the project folder:

   ```
   POSTGRES_PASSWORD=choose-a-password-with-letters-and-numbers
   SECRET_KEY=generate-a-long-random-string
   ```

   You can generate a key with:

   ```
   python -c "import secrets; print(secrets.token_hex(32))"
   ```

2. Start the app:

   ```
   docker compose up --build
   ```

3. Open http://127.0.0.1:8000/docs

Migrations run automatically when the API container starts.

## Run locally (without Docker)

Requires Python 3.12 and PostgreSQL.

1. Create a database and a user in PostgreSQL.
2. Create and activate a virtual environment, then install dependencies:

   ```
   python -m venv .venv
   .venv\Scripts\Activate.ps1      # Windows PowerShell
   pip install -r requirements.txt
   ```

3. Create a `.env` file:

   ```
   DATABASE_URL=postgresql+psycopg://USER:PASSWORD@localhost:5432/DBNAME
   SECRET_KEY=generate-a-long-random-string
   ```

4. Apply the migrations and start the server:

   ```
   alembic upgrade head
   uvicorn main:app --reload
   ```

## Run the tests

The tests use a separate database whose name must end in `_test`, so they can never touch real data. Add its URL to `.env`:

```
TEST_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@localhost:5432/DBNAME_test
```

Then run:

```
pytest -v
```

## Design decisions

- **Argon2 for password hashing.** It is deliberately slow and salted, which makes brute-forcing leaked hashes expensive.
- **Access control in the query, not after it.** Task lookups filter by task id and owner id together, so a forgotten check can't leak another user's data.
- **404 instead of 403 for other users' tasks.** A 403 would confirm the task exists. A 404 reveals nothing.
- **Same error for wrong email and wrong password.** The login endpoint doesn't reveal which emails are registered.
- **Alembic instead of `create_all`.** Schema changes are versioned and reversible, and they don't require dropping tables.
- **Separate test database with a safety guard.** The test setup refuses to run unless the database name ends in `_test`.
- **Non-root user in the Docker image.** It limits the damage if the app is ever compromised.
- **Secrets only in environment variables.** `.env` is ignored by Git and excluded from the Docker image.

## Known limitations

- No frontend. The API is used through the generated `/docs` page.
- No rate limiting on login.
- Access tokens expire after 30 minutes, and there are no refresh tokens.
- CI doesn't yet test the migrations.
- Deployed on a free host with a temporary database
